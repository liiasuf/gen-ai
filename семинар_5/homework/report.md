## 1. Новый инструмент `compare_periods`

### Сигнатура

```python
def compare_periods(
    metric: str,     # "key_rate" | "fx_USD" | "fx_EUR" | "fx_CNY" | "cpi" | "unemployment"
    period_a: str,   # "YYYY-MM" или "YYYY-MM-DD"
    period_b: str,
) -> dict:
    """
    Сравнить значение метрики в двух периодах.
    Возвращает:
      {"metric": ...,
       "a": {"date": ..., "value": ...},
       "b": {"date": ..., "value": ...},
       "delta": b.value - a.value,
       "ratio": b.value / a.value,
       "source": "..."}
    """
```

Внутри функция вызывает существующие `get_fx_rate`, `get_key_rate`, `get_inflation`, `get_unemployment` — логика не дублируется. Поддерживает формат `"YYYY-MM"` (преобразуется в первый день месяца).

### Примеры вызовов

**Q5 — «Во сколько раз вырос курс USD с января 2022 по апрель 2026?»**
```json
{"metric": "fx_USD", "period_a": "2022-01", "period_b": "2026-04"}
→ {"a": {"date": "2022-01-04", "value": 74.68},
   "b": {"date": "2026-04-01", "value": 89.57},
   "delta": 14.89, "ratio": 1.1994, "source": "fallback_csv"}
```

**Q6 — «Как изменилась инфляция между декабрём 2021 и декабрём 2024?»**
```json
{"metric": "cpi", "period_a": "2021-12", "period_b": "2024-12"}
→ {"a": {"date": "2021-12", "value": 8.39},
   "b": {"date": "2024-12", "value": 9.52},
   "delta": 1.13, "ratio": 1.1347, "source": "rosstat_csv"}
```

**Ещё один пример — «Насколько упала ключевая ставка с декабря 2024 по апрель 2026?»**
```json
{"metric": "key_rate", "period_a": "2024-12", "period_b": "2026-04"}
→ {"a": {"date": "2024-12-31", "value": 21.0},
   "b": {"date": "2026-04-01", "value": 16.0},
```

## 3. Диагностика трёх ошибок

### Ошибка 1: Битый JSON в аргументах

**Тип:** битый JSON в аргументах инструмента.

**Трасса** (run_id `err-0007-bitjson-...`, Q7):
```
step 1 → call: get_fx_rate
         args: {}
         obs:  {"error": "битый json аргументов: Expecting value: line 1 column 1 (char 0)"}
step 2 → call: get_fx_rate
         args: {"currency": "USD", "on_date": "2022-02-01"}
         obs:  {"currency": "USD", "date": "2022-01-04", "rate": 74.68, "source": "fallback_csv"}
step 3 → final: "В начале февраля 2022 года курс..."
```

**Причина:** при вопросе «начало февраля 2022» модель сначала вызвала инструмент с пустым `arguments` (пустая строка `""` вместо `"{}"`). `json.loads("")` бросает `JSONDecodeError`. Обработчик `_exec_one` перехватил и вернул `{"error": ...}`, модель исправилась и повторила вызов корректно.

**Что исправить:** в `_exec_one` добавить нормализацию: `arguments = tc.function.arguments or "{}"` уже стоит, но некоторые модели шлют не пустую строку, а `"null"` или `" "`. Нужен более надёжный fallback:
```python
raw = tc.function.arguments or "{}"
if raw.strip() in ("", "null"):
    raw = "{}"
args = json.loads(raw)
```

### Ошибка 2: Неправильный порядок вызовов

**Тип:** неправильный порядок вызовов — агент запросил данные за соседний период вместо нужного.

**Трасса** (run_id `err-0008-hallu-...`, Q8):
```
step 1 → call: get_inflation(year=2022, month=3)
         obs:  {"cpi_yoy": 16.69, "source": "rosstat_csv"}
step 1 → call: get_unemployment(year=2022, month=3)
         obs:  {"unemployment": 4.0}
step 2 → call: get_unemployment(year=2022, month=2)  ← лишний вызов!
         obs:  {"unemployment": 4.1}
step 3 → call: calculate(expression="16.69 + 4.1")   ← использует февральское значение
         obs:  {"result": 20.79}
step 4 → final: "Индекс нищеты... 20,79%"
```

**Причина:** модель «перепроверила» безработицу за февраль (предыдущий месяц), затем случайно использовала результат этого вызова в итоговом `calculate` вместо мартовского. Промпт не запрещает делать лишние вызовы, и модель не понимает, что надо брать ровно тот месяц, который указан в вопросе.

**Что исправить:** в системном промпте добавить правило: «Если вопрос содержит конкретный месяц — делай ровно один вызов инструмента для этого месяца, не проверяй соседние». Альтернатива — в `calculate` передавать выражение с именованными переменными и проверять консистентность.

### Ошибка 3: Бесконечный (многократный) повтор одного вызова

**Тип:** избыточный цикл — модель повторяет один и тот же вызов инструмента несколько раз.

**Трасса** (run_id `err-0009-loop-...`, Q9):
```
step 1 → call: get_fx_rate(currency="EUR")  → rate=97.12
step 1 → call: get_fx_rate(currency="USD")  → rate=89.57
step 2 → call: calculate("1000 * 89.5678 / 97.1234")  → 922.24
step 3 → call: calculate("1000 * 89.5678 / 97.1234")  → 922.24   ← дубль!
step 4 → call: calculate("1000 * 89.5678 / 97.1234")  → 922.24   ← дубль!
step 5 → final: "За 1000 долларов можно купить около 922 евро..."
```

**Причина:** модель не получила подтверждения от `calculate` (сообщение tool-role было добавлено в messages, но модель по какой-то причине решила пересчитать ещё раз — это типичное поведение при недостаточно строгой инструкции «считай ТОЛЬКО один раз»). Без кэша каждый дубль — лишний вызов инструмента.

**Что исправить:** (1) включить `--cache` — тогда повторный вызов `calculate` с теми же аргументами не будет исполняться, а вернётся из кэша мгновенно; (2) в системном промпте добавить: «Если результат `calculate` уже получен и в ответе нет `"error"` — не вызывай его снова с теми же аргументами».

## 4. Вывод: самый хрупкий элемент системы

Самый хрупкий элемент — **разрешение дат и периодов в промпте**. Когда пользователь пишет «начало февраля», «весна 2022» или «последний квартал» — модель должна сама определить конкретную дату. При этом нет жёсткого механизма проверки: агент может взять соседний месяц, ближайшую запись из fallback_csv, или сделать лишний вызов «на всякий случай». Все три ошибки в этом отчёте так или иначе связаны с неоднозначностью временного контекста.
